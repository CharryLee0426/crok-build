Crok Desktop 2.0.4 は、このフォーク向けのネイティブ macOS アプリです。エージェントのランタイムであり `crok` ターミナル UI でもある crok を同梱しているので、ほかに何もインストールする必要はありません。これは、どのデバイスのセッション一覧も最新の状態に保つようにした 2.0.3 に続くリリースです。2.0.4 では、Web、スマートフォン、ほかのコンピューターから送るプロンプトに写真やファイルを添えられるようになり、それらはどのデバイスのトランスクリプトにも表示されます。すべてのセッション一覧に**更新**ボタンが加わり、オンラインの各コンピューターにセッションをすぐに一覧し直させます。Crok Desktop はすべての応答の下にコピーと高評価・低評価のボタンを表示し、ターミナルはターンの後に短い質問を 1 つ尋ねます。また、OpenRouter のより多くの推論モデルがセッションに名前を付けられるようになりました。

このリリースも 2.0.3 と同様に、プルリクエストがマージされるとすぐに GitHub Actions がビルドして公開します。

### インストール

1. お使いの macOS のバージョンに合ったディスクイメージをダウンロードして開きます。どちらを選ぶかは**どのディスクイメージをダウンロードするか**の表をご覧ください。
2. **Crok Desktop** を**アプリケーション**にドラッグします。
3. アプリケーションから Crok Desktop を開きます。このビルドは公証されていないため、初回は macOS がアプリを検証できないと表示します。メッセージを閉じ、**システム設定 › プライバシーとセキュリティ**を開いて、Crok Desktop のメッセージの横にある**このまま開く**をクリックし、確認してください。この操作は一度だけです。
4. **設定 › アカウント**で、OpenRouter、OpenAI Codex、Anthropic API キー、DeepSeek API キー、または GLM Coding Plan のキーでサインインします。

Apple シリコン（M1 以降）を搭載した Mac と、macOS 14 Sonoma 以降が必要です。

### どのディスクイメージをダウンロードするか

どちらのイメージも Crok Desktop 2.0.4 で、機能は同じです。違いはビルドに使った macOS SDK だけで、これによってウインドウの外観に Apple の Liquid Glass が使われるかどうかが決まります。

| ディスクイメージ | ビルドに使った SDK | 対象 | タイトルバー |
| --- | --- | --- | --- |
| `Crok-Desktop-2.0.4-arm64-macOS26-SDK.dmg` | macOS {{SDK26}} SDK | macOS 26 以降 | Liquid Glass |
| `Crok-Desktop-2.0.4-arm64-macOS15-SDK.dmg` | macOS {{SDK15}} SDK | macOS 14 と 15 | ウインドウ内のすりガラス風のぼかし |

macOS 26 以降では、タイトルバーが Liquid Glass になる macOS 26 SDK のイメージをおすすめします。macOS 14 または 15 では、macOS 15 SDK のイメージを使ってください。こちらはそれ以降のバージョンでも動くので、macOS のバージョンがわからない場合はこちらが安全です。

`crok-2.0.4-aarch64-apple-darwin.tar.gz` は `crok` ターミナル UI 単体で、アプリを入れたくない Mac 向けです。展開して `crok` を `PATH` の通った場所に置いてください。スマートフォンアプリについては、**スマートフォンアプリ**で説明しています。`SHA256SUMS.txt` はすべてのダウンロードファイルの SHA-256 の一覧、`SHA256SUMS.txt.sig` はその一覧の署名で、アップデート機能がこれを検証します。

### スマートフォンアプリ

iPhone と Android 向けの Crok アプリは、お使いのコンピューターのセッションを追いかけ、その応答と権限の要求を表示し、どこからでもタスクを開始したり操作したりできます。このリリースのスマートフォンアプリは新しくなりました。プロンプトに写真やファイルを添えて送り、それらをトランスクリプトに表示し、**更新**ボタンを備えています。どちらも使うには、2.0.3 のスマートフォンアプリの上にこのリリースのものをインストールしてください。2.0.3 以前のスマートフォンアプリも、これらの機能なしでこれまでどおり動作します。3 つのファイルはいずれも本番リレーにサインインします。

- **Android 8.0 以降**：スマートフォンで `Crok-Android-2.0.4.apk` をダウンロードして開きます。Android に求められたら、ブラウザにアプリのインストールを許可してください。または `adb install -r Crok-Android-2.0.4.apk` を実行します。この APK は 2.0.0 で導入されたリリース用の鍵で署名されているため、以前のリリースの APK の上にそのままインストールできます。自分でビルドした Crok の APK は別の鍵で署名されていて、インストールを妨げます。先に `adb uninstall dev.chenli.crok.mobile` を実行するか、スマートフォンの設定から削除してください。
- **iPhone と iPad、iOS 17 以降**：`Crok-iOS-2.0.4-unsigned.ipa` は署名されていません。iOS デバイス向けのアプリは、インストールする人の Apple ID で署名されるためです。AltStore や Sideloadly などのサイドロードツールでインストールしてください。これらのツールがお使いの Apple ID で署名します。無料の Apple ID の場合、7 日たつと、もう一度インストールするまで iOS はアプリを開かなくなります。代わりに自分でビルドする場合は、**Release** 構成を使ってください。Xcode の Run ボタンは Debug をビルドし、そちらはテスト用リレーにサインインします。
- **iOS シミュレータ**：`Crok-iOS-2.0.4-Simulator.zip` を展開すると `Crok.app` になります。Xcode のある Mac で `xcrun simctl install booted Crok.app` を実行するためのものです。

スマートフォンをサインインさせるには、**GitHub または Google で続ける**をタップし、開いた https://crok.chenli.dev のページでサインインして、**承認**をタップします。続いて、各コンピューターをリンクします。そのコンピューターで `crok remote login` を実行し、表示された QR コードをアプリの**設定 › コンピュータをリンク**から読み取るか、開いた Web ページでそのコンピューターを承認してください。

### ハイライト

- **どのデバイスからでも、プロンプトに写真やファイルを添えられます。** Web とスマートフォンアプリでは、入力欄の横にあるクリップのボタン（添付）から、プロンプトに写真やファイルを追加できます。スマートフォンでは「写真」「カメラ」「ファイル」から選べ、Web ではセッションへの貼り付けやドロップでも追加できます。1 つのメッセージで最大 10 件、1 件あたり 20 MB まで送れ、写真だけのメッセージも送れます。コンピューターは画像を画像としてモデルに渡し、それ以外のファイルは専用のフォルダーに保存してモデルが読めるようにします。写真はどのデバイスのトランスクリプトにも表示され、タップすると全画面で開きます（スマートフォンでは**共有**と**保存**が使えます。iPhone では**写真に保存**と表示されます）。コンピューター自身で入力したプロンプトの画像も、スマートフォンと Web に表示されます。
- **すべてのセッション一覧を更新できます。** Web、スマートフォンアプリ、Crok Desktop の**ほかのコンピューター**、ターミナルのリモートパネルに、「更新」の操作（↻、または `/remote` での `r`）が加わりました。オンラインのすべてのコンピューターに、次の確認を待たずにすぐにすべてのセッションを一覧し直すよう求め、それぞれが終えるまでアイコンが回り続けます。スマートフォンでは、一覧を下に引っ張っても同じことができます。
- **応答へのフィードバック。** Crok Desktop は、完了したすべての応答の下に**コピー**と高評価・低評価のボタンを表示します。コピーは応答の Markdown を書かれたとおりに取り込み、選んだ評価のボタンをもう一度クリックすると評価を取り消せます。ターミナルは完了したターンの下に「この回答はいかがでしたか？」と一度だけ尋ね、`/good`、`/not-so-well`、`/dont-show-again` で答えます。
- **より多くの OpenRouter モデルでセッションにタイトルが付きます。** 強制されたツール呼び出しを拒む推論モデル（Muse Spark 1.3）や、短い回答に割り当てられた分を推論に使い切ってしまう推論モデル（Muse Glimmer、GLM 5.3 Flash、Aion 2.0）には、生成されたタイトルが付かず、セッションにはプロンプトの最初の数語から名前が付いていました。今はほかのモデルと同じようにタイトルが付きます。

### リモートコントロール

このリリースのすべての crok は、2.0.3 と同じく https://crok.chenli.dev の本番リレーにサインインし、すでにあるサインインをそのまま使います。本番リレーには、このリリースが公開されるときに、このリリースのリレー側の変更が反映されます。コンピューター上で行われる部分は、そのコンピューターの crok 2.0.4 で使えるようになります。

- **写真とファイル（コンピューター）。** crok は、そうしたプロンプトを実行する前に、その写真とファイルをダウンロードします。画像は画像入力としてモデルに渡されます。それ以外のファイルは `~/.crok/remote/attachments/` の下（セッションとメッセージごとに 1 つのフォルダー）に保存され、Crok Desktop がファイルを添付するときと同じように、プロンプトの中でリンクされます。すでに開いているほかのコンピューターのタスクでは、Crok Desktop とターミナルも、プロンプトの画像とファイルを一緒にアップロードします。ほかのコンピューターでの新しいタスクは、これまでどおりテキストだけで始まります。
- **写真とファイル（リレー）。** Web とスマートフォンは、写真を正しい向きに直し、長辺を最大 2048 ピクセルにし、メタデータを取り除いたうえで、小さなプレビューとともに送ります。どのメッセージにも結び付かなかったアップロードは 1 日後に削除されます。セッションのファイルは、セッションと一緒に削除されるか、操作のないまま 30 日たってトランスクリプトが削除されるときに一緒に削除されます。
- **古い crok。** crok 2.0.3 以前しか動いていないコンピューターは、写真やファイルを受け取れません。そこへ送ろうとすると、「Update crok on … to send photos and files there.」（… の crok を更新すれば、そこに写真やファイルを送れる、という意味）と表示されます。テキストのプロンプトはこれまでどおり使えます。
- **更新。** コンピューターのセッション一覧を受け持つ crok は、誰かが「更新」を押すとすぐにディスク上のすべてのセッションを一覧し直し、その後はこれまでどおり、30 秒ごとに変わった部分だけを送り続けます。回転するアイコンは、オンラインのすべてのコンピューターが応答するか、15 秒たつと止まります。古い crok しか動いていないコンピューターは、次の定期的な一覧の送信まで応答しないことがあります。オフラインのコンピューターはセッションを一覧できないため、そのセッションは最後に一覧されたときのままになります。オンラインのコンピューターが 1 台もないとき、スマートフォンと Web には「オンラインのコンピューターがありません。前回の一覧を表示しています。」と表示されます。
- **コンピューターを更新してください。** プロンプトの写真とファイル、そして「更新」への即時の応答は、各コンピューターの crok 2.0.4 で使えるようになります。

### フィードバックと Agent Observability

2.0.3 と同様に、このリリースのすべての crok は、自分が行うモデル呼び出しを 1 回ごとに、そのターン、ツール実行、ステップ、ガードのチェックとあわせて、メンテナーの Grafana Cloud スタック上の [Grafana Agent Observability](https://grafana.com/docs/grafana-cloud/machine-learning/agent-observability/) に報告します。報告先のホストは `crok version --json` の `agentObservability` に表示されます。

- **評価の行き先。** Crok Desktop またはターミナルからの高評価・低評価は、Agent Observability ではそのターンの会話に記録され、`crok_feedback_rating` ゲージとしても記録されます。評価を取り消すと中立として記録され、数に入らなくなります。報告がオフの間は何も送られません。
- **ターミナルの質問。** 完了したターンの下に一度だけ表示されます。キャンセルされたターンや失敗したターンの後、ミニマルモード、行数のごく少ないターミナルでは表示されません。`/dont-show-again` は、`~/.crok/config.toml` の `[features]` に `feedback_prompt = false` を書き込んで質問をオフにします。もう一度質問を表示するには、`true` に戻してください。
- **メンテナーによる評価。** 新しい **crok Feedback** ダッシュボードは、フィードバックのあるターンのうち高評価の割合を示します。1 日を通じて 80% を下回るとアラートが出るほか、30 日間の目標も設定されています。これらは、期間内に 20 件以上の評価がある場合に適用されます。

報告をやめるには、`~/.crok/config.toml` の `[features]` に `agent_observability = false` を追加するか、`CROK_AGENT_OBSERVABILITY=0` を設定します。自分のスタックに報告するには、リポジトリの `crates/codegen/xai-grok-agento11y/setup.sh` で `~/.crok/agento11y.env` を書きます。

### 開発者向け

- リリースはこれまでどおり `.github/workflows/release.yml` が行います。`VERSION` を上げたプルリクエストが `main` にマージされると、すべてのファイルをビルド、検証、署名し、評価ゲートを実行して、`release/notes/v2.0.4/` のノートとともにリリースを公開します。
- 写真とファイル：デバイスは `files:uploadUrl` にアップロードし、`commands:sendPrompt` と `sessions:create` でそのアップロードを指定します（`attachments`）。リレーはそれらを `files` テーブル（所有者、セッション、SHA-256、プレビュー）に保持し、コンピューターの受信箱とすべてのトランスクリプトのクエリにダウンロード URL を渡します。こうしたプロンプトは、`features` に `attachments` を挙げている crok にだけ渡され、`bridge:connect` はリレー自身の `features` を返します。`relay/DESIGN.md` §2–§5 の「Photos and files」が仕様で、`relay/scripts/attachments-e2e.mjs` と `attachments-bridge-e2e.mjs` がそれを検証します。
- 更新：`sessions:refresh`（`{asked, offline, at}`）は、オンラインの各コンピューターのカタログに `refreshAt` を記録します。それが最後のアップロードの開始より後である間、そのコンピューターのすべての crok には `catalogWanted` が見え、`bridge:beginCatalog` は最初に求めたもの（保持者も含みます）にすぐ許可を与えます。`sessions:refreshState({since})` は、まだ一覧中のコンピューターを示します。ビューアーの `x.ai/remote/refresh` は、Crok Desktop とターミナルのためにこの両方を行います。`relay/scripts/refresh-e2e.mjs` は、実際の crok プロセスでこれを検証します。
- フィードバック：フロントエンドはターンについて `x.ai/feedback/rating`（`1`、`-1`、取り消しは `0`）を送ります。`[features] feedback_prompt`（既定は `true`、`CROK_FEEDBACK_PROMPT`）がターミナルの質問を制御します。評価には、`crok Feedback` ダッシュボード、`crok-feedback-good-rate-low` アラート、`crok feedback is mostly positive` SLO を使います。
- OpenRouter では、サンプラーは強制ツール呼び出しを `tool_choice: "auto"` のまま言葉で求めます。推論モデルには、呼び出しが effort を指定しない限りカタログに載っている最も軽い effort を使い、少なくとも 4,096 の出力トークンを与えます。`SamplerConfig` の 2 つのフィールドが、カタログの推論対応と最も軽い effort を保持します。
- **LLM Overview** ダッシュボードのキャッシュヒット率は、Claude Platform、OpenRouter、crok 自身が報告する呼び出しを対象にするようになりました。それぞれを個別にクエリするため、期間内に呼び出しのないソースは何も加えません。

### 署名

2.0.4 は、2.0.3、2.0.2、2.0.1、2.0.0、1.5.2、1.5.3 と同じ "Crok Code Signing" 証明書で署名されています。macOS はプライバシー権限を署名に結び付けているため、2.0.3 に許可したもの（「画面収録」、「アクセシビリティ」、マイク、音声認識）は 2.0.4 に引き継がれます。このビルドは公証されていないので、新しくインストールする場合は上記の**このまま開く**の手順が一度必要です。

Android アプリは、2.0.0 で導入されたリリース用の鍵で署名されています。iOS アプリは、**スマートフォンアプリ**で説明しているとおり署名されていません。署名付きのチェックサム一覧は、これとは別のものです。アップデート機能がダウンロードしたファイルを検証するためのもので、macOS によるアプリの扱いは変わりません。

### 2.0.3 からのアップグレード

**Crok Desktop › アップデートを確認…** を使うか、Crok Desktop を終了してからターミナルで `crok upgrade` を実行します。今回のアップデートは、インストール済みの `Crok Desktop.app` にそのまま行われます。そのため Dock や Finder での位置はそのままで、古いコピーがゴミ箱に残ることもありません。アップデートは、インストール済みのアプリと同じ SDK でビルドされたイメージ（macOS26-SDK または macOS15-SDK）を取得し、もう一方になることはありません。

モデルプロバイダへのサインイン、設定、タスク、リレーはいずれも引き継がれます。2.0.4 は 2.0.3 と同じ本番リレーと通信します。リレーで使うコンピューターはすべて更新してください。そうすれば、写真やファイルを受け取り、「更新」にすぐ応答できるようになります。また、上の**スマートフォンアプリ**で説明しているとおり、このリリースのスマートフォンアプリをインストールしてください。

### 詳細

- crok `{{CROK_VERSION}}` を同梱しています。
- GitHub Actions が、`main` のタグ `desktop-v2.0.4`（`{{COMMIT}}`）からビルドしました。macOS 26 SDK のイメージは Xcode {{XCODE26}} と macOS {{SDK26}} SDK、macOS 15 SDK のイメージは Xcode {{XCODE15}} と macOS {{SDK15}} SDK、単体の `crok` は macOS {{TUI_SDK}} SDK でビルドしています。
- どちらのイメージも arm64 で、Crok Code Signing 証明書による署名あり、公証なしです。どちらも macOS 14 Sonoma 以降で動作します。
- iOS アプリ（`dev.chenli.crok.mobile`）は Xcode {{XCODE26}} で作った Release ビルド、Android アプリは Android 8.0 以降向けのリリースビルドです。
- SHA-256 チェックサムは、このノートの末尾と、スマートフォンアプリも含む `SHA256SUMS.txt` にあります。一覧の署名を手作業で確認する方法は、リポジトリの `release/README.md` にあります。
