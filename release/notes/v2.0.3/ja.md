Crok Desktop 2.0.3 は、このフォーク向けのネイティブ macOS アプリです。エージェントのランタイムであり `crok` ターミナル UI でもある crok を同梱しているので、ほかに何もインストールする必要はありません。2.0.3 は 2.0.2 に続くリリースで、2.0.2 ではブラウザーツールがお使いの Chrome で動くようになり、どのデバイスでもモデルを選べるようになりました。2.0.3 では、どのデバイスのセッション一覧も最新の状態に保たれます。コンピューターで作成、名前変更、削除したセッションは、約 30 秒以内に Web、スマートフォン、ほかのコンピューターに届きます。Web やスマートフォンからコンピューター上で始めたセッションは、そのコンピューターにも表示されるようになりました。Crok Desktop ではタスクとして、ターミナルではリモートパネルに表示されます。モデルを選んで始めた新しいセッションは必ずそのモデルで始まり、crok の Claude 呼び出しが Agent Observability で二重に数えられることもなくなりました。

このリリースも 2.0.2 と同様に、プルリクエストがマージされるとすぐに GitHub Actions がビルドして公開します。

### インストール

1. お使いの macOS のバージョンに合ったディスクイメージをダウンロードして開きます。どちらを選ぶかは**どのディスクイメージをダウンロードするか**の表をご覧ください。
2. **Crok Desktop** を**アプリケーション**にドラッグします。
3. アプリケーションから Crok Desktop を開きます。このビルドは公証されていないため、初回は macOS がアプリを検証できないと表示します。メッセージを閉じ、**システム設定 › プライバシーとセキュリティ**を開いて、Crok Desktop のメッセージの横にある**このまま開く**をクリックし、確認してください。この操作は一度だけです。
4. **設定 › アカウント**で、OpenRouter、OpenAI Codex、Anthropic API キー、DeepSeek API キー、または GLM Coding Plan のキーでサインインします。

Apple シリコン（M1 以降）を搭載した Mac と、macOS 14 Sonoma 以降が必要です。

### どのディスクイメージをダウンロードするか

どちらのイメージも Crok Desktop 2.0.3 で、機能は同じです。違いはビルドに使った macOS SDK だけで、これによってウインドウの外観に Apple の Liquid Glass が使われるかどうかが決まります。

| ディスクイメージ | ビルドに使った SDK | 対象 | タイトルバー |
| --- | --- | --- | --- |
| `Crok-Desktop-2.0.3-arm64-macOS26-SDK.dmg` | macOS {{SDK26}} SDK | macOS 26 以降 | Liquid Glass |
| `Crok-Desktop-2.0.3-arm64-macOS15-SDK.dmg` | macOS {{SDK15}} SDK | macOS 14 と 15 | ウインドウ内のすりガラス風のぼかし |

macOS 26 以降では、タイトルバーが Liquid Glass になる macOS 26 SDK のイメージをおすすめします。macOS 14 または 15 では、macOS 15 SDK のイメージを使ってください。こちらはそれ以降のバージョンでも動くので、macOS のバージョンがわからない場合はこちらが安全です。

`crok-2.0.3-aarch64-apple-darwin.tar.gz` は `crok` ターミナル UI 単体で、アプリを入れたくない Mac 向けです。展開して `crok` を `PATH` の通った場所に置いてください。スマートフォンアプリについては、**スマートフォンアプリ**で説明しています。`SHA256SUMS.txt` はすべてのダウンロードファイルの SHA-256 の一覧、`SHA256SUMS.txt.sig` はその一覧の署名で、アップデート機能がこれを検証します。

### スマートフォンアプリ

iPhone と Android 向けの Crok アプリは、お使いのコンピューターのセッションを追いかけ、その応答と権限の要求を表示し、どこからでもタスクを開始したり操作したりできます。2.0.2 と同様にこのリリースに含まれ、動作も 2.0.2 のものと同じです。このリリースの変更はコンピューターとリレーの側にあるので、2.0.2 や 2.0.1 のスマートフォンアプリにもそのまま反映されます。3 つのファイルはいずれも本番リレーにサインインします。

- **Android 8.0 以降**：スマートフォンで `Crok-Android-2.0.3.apk` をダウンロードして開きます。Android に求められたら、ブラウザにアプリのインストールを許可してください。または `adb install -r Crok-Android-2.0.3.apk` を実行します。この APK は今後のリリースでも使い続けるリリース用の鍵で署名されているため、次の APK はこの上にそのままインストールできます。自分でビルドした Crok の APK は別の鍵で署名されていて、インストールを妨げます。先に `adb uninstall dev.chenli.crok.mobile` を実行するか、スマートフォンの設定から削除してください。
- **iPhone と iPad、iOS 17 以降**：`Crok-iOS-2.0.3-unsigned.ipa` は署名されていません。iOS デバイス向けのアプリは、インストールする人の Apple ID で署名されるためです。AltStore や Sideloadly などのサイドロードツールでインストールしてください。これらのツールがお使いの Apple ID で署名します。無料の Apple ID の場合、7 日たつと、もう一度インストールするまで iOS はアプリを開かなくなります。代わりに自分でビルドする場合は、**Release** 構成を使ってください。Xcode の Run ボタンは Debug をビルドし、そちらはテスト用リレーにサインインします。
- **iOS シミュレータ**：`Crok-iOS-2.0.3-Simulator.zip` を展開すると `Crok.app` になります。Xcode のある Mac で `xcrun simctl install booted Crok.app` を実行するためのものです。

スマートフォンをサインインさせるには、**GitHub または Google で続ける**をタップし、開いた https://crok.chenli.dev のページでサインインして、**承認**をタップします。続いて、各コンピューターをリンクします。そのコンピューターで `crok remote login` を実行し、表示された QR コードをアプリの**設定 › コンピュータをリンク**から読み取るか、開いた Web ページでそのコンピューターを承認してください。

### ハイライト

- **どのデバイスのセッション一覧も最新の状態に保たれます。** コンピューターのディスク上だけで変わったセッション（リレーにサインインしていない crok が作ったもの、名前を変えたもの、削除したもの）は、これまでそのコンピューターが次に一覧全体を送るまで、Web、スマートフォン、ほかのコンピューターに届きませんでした。一覧全体の送信は約 20 分ごとで、送っている crok が終了すると止まっていました。今は約 30 秒以内に届き、最初の crok が終了するとすぐに、そのコンピューターの別の crok が一覧の送信を引き継ぎます。
- **Web やスマートフォンから始めたセッションが、そのコンピューターに表示されます。** Crok Desktop はそうしたセッションを、そのプロジェクトの未読のタスクとして追加し、ターンの実行中は作業中と表示します。ターミナルは、どのデバイスがそのセッションを始めたかを知らせ、`/remote` の**このコンピュータ**の下に一覧表示します。
- **新しいセッションが選んだモデルで始まります。** Web やスマートフォンからモデルと思考レベルを選んで始めたセッションは、そのコンピューターの古い crok（たとえばアップデート前から開いたままのターミナル）が先に受け取ると、選んだものではなくコンピューターの既定の設定で始まることがありました。今は、その選択を適用できる crok だけがセッションを受け取れます。
- **ほかのコンピューターの一覧がすぐに表示されます。** Crok Desktop の**ほかのコンピューター**は、リレーへの接続がつながるたびに一覧を求め直し、返事があるまで 5 秒ごとに繰り返します。以前は最大 4 分待っていました。
- **Claude の呼び出しが Agent Observability に一度だけ報告されます。** Claude Platform 自身のテレメトリーのエクスポートが、crok が報告したすべての Claude 呼び出しの 2 つ目のコピーを保存していました。crok は今、自分で報告する呼び出しをエクスポートしないよう Anthropic の API に求めます。下の **Agent Observability** を参照してください。

### リモートコントロール

このリリースのすべての crok は、2.0.2 と同じく https://crok.chenli.dev の本番リレーにサインインし、すでにあるサインインをそのまま使います。本番リレーではこのリリースのリレー側の変更がすでに動いているので、下の「選んだモデル」の規則は今日から適用されます。それ以外は、各コンピューターの crok 2.0.3 で使えるようになります。

- **セッション一覧。** 各コンピューターでは、1 つの crok がそのコンピューターの一覧を受け持ちます。この crok は 30 秒ごとにディスク上のセッションを調べて変わった部分だけを送り、30 分ごとに一覧全体を送り直します。この crok が終了するか接続を失うと、そのコンピューターのほかのすべての crok に一覧の引き継ぎが依頼され、最初に応じたものが引き継ぎます。crok が再び起動したコンピューターは、すぐにセッションの一覧を送ります。crok 2.0.2 以前を使っているコンピューターは引き続き自分で一覧全体を送りますが、その間隔は約 20 分ごとから 10 分ごとになりました。
- **ほかの場所で始めたセッション（Crok Desktop）。** ほかのデバイスがこの Mac で始めたセッションは、リレーの一覧に載るとすぐに、そのプロジェクトのタスクになります。そのフォルダーのプロジェクトがアプリにない場合は、プロジェクトも追加されます。このタスクは未読で、開くまではセッションのタイトルが付き、そこでターンが実行されている間は作業中、ターンが終わると未読と表示されます。ほかのタスクと同じように開けます。こうしたセッションはそれぞれ一度だけ追加されるので、削除したタスクやプロジェクトが戻ってくることはありません。
- **ほかの場所で始めたセッション（ターミナル）。** ターミナルはリレーに接続している間、ほかのデバイスがこのコンピューターで始めたセッションを 1 つずつ知らせます。たとえば「iPhone が app でセッションを開始しました: … — /resume か /remote で開けます」のように表示されます。リモートパネルはそうしたセッションを**このコンピュータ**の下の先頭に並べ、それぞれにどのデバイスから来たか（「iPhone から」）を示します。Enter でそのセッションをここで開けます。また、このコンピューターに対して `n` を押すと、`/new` を使うよう案内されます。
- **選んだモデル。** モデルや思考レベルを指定した新しいセッションは、それを適用できる crok（crok 2.0.1 以降）にだけ渡されます。crok 2.0.0 以前しか動いていないコンピューターでは、そうしたセッションは既定の設定で始まるのではなく、「Update crok on … to start a session there with a chosen model or thinking level」（… の crok を更新すれば、選んだモデルや思考レベルでそこにセッションを始められる、という意味）というメッセージで失敗します。**デフォルト**のままのセッションは、これまでどおりどの crok でも始まります。開始に失敗したセッションを開き直すプロンプトや再試行にも、同じ規則が適用されます。
- **コンピューターを更新してください。** ディスクの変化に追いつく一覧と、ほかのデバイスから始めたセッションがそのコンピューターに表示される機能は、そのコンピューターの crok 2.0.3 で使えるようになります。スマートフォン側は何も変わりません。

### Agent Observability

2.0.2 と同様に、このリリースのすべての crok は、自分が行うモデル呼び出しを 1 回ごとに、そのターン、ツール実行、ステップ、ガードのチェックとあわせて、メンテナーの Grafana Cloud スタック上の [Grafana Agent Observability](https://grafana.com/docs/grafana-cloud/machine-learning/agent-observability/) に報告します。報告先のホストは `crok version --json` の `agentObservability` に表示されます。

- **Claude 呼び出しの 2 つ目のコピーは作られなくなりました。** Claude Platform の組織は、すべての API リクエストのトレーススパンを自分のテレメトリーの送信先にエクスポートできます。Agent Observability はそのそれぞれを、トレース ID を名前にした独立した会話として、エージェント `claude-platform` の下に保存していました。そのため、crok が報告したすべての Claude 呼び出しが 2 回保存されていました。crok は今、自分が報告する呼び出しを、サンプリングしないと示したトレースコンテキスト付きで `api.anthropic.com` に送ります。Anthropic の API はこれに応じて、その呼び出しについて何もエクスポートしません。crok が報告しない呼び出し（圧縮と、報告がオフの間のすべての呼び出し）はこれまでどおりエクスポートされ、ほかのプロバイダーへの呼び出しも同様です。
- **組織で Claude のテレメトリーをエクスポートしている場合、** crok が Agent Observability に報告する Claude 呼び出しは、そのエクスポートには含まれなくなります。そこに再び含めたい場合は、報告をオフにしてください。
- **ダッシュボードは crok の Claude 呼び出しを、Claude Platform の代わりに数えます。** そうした呼び出しの crok のスパンには `crok.unsampled = true` が付き、キャッシュの読み取りと思考トークンを Claude Platform の属性名で持つので、LLM Observability のダッシュボードはそれを一度だけ数えます。crok 2.0.2 以前からの呼び出しは、引き続き Claude Platform のエクスポートから数えます。
- **すでに保存されたコピーには印が付いています。** Agent Observability は保存したものを削除できないため、crok 1.5.0 から 2.0.2 までが作った 586 件のコピーそれぞれに、crok の呼び出しのコピーであることを示すラベルを付けました。これで、Claude Platform だけが見た呼び出しと区別できます。crok 2.0.2 以前のままのコンピューターは、更新されるまでコピーを増やし続けます。

報告をやめるには、`~/.crok/config.toml` の `[features]` に `agent_observability = false` を追加するか、`CROK_AGENT_OBSERVABILITY=0` を設定します。自分のスタックに報告するには、リポジトリの `crates/codegen/xai-grok-agento11y/setup.sh` で `~/.crok/agento11y.env` を書きます。

### 開発者向け

- リリースはこれまでどおり `.github/workflows/release.yml` が行います。`VERSION` を上げたプルリクエストが `main` にマージされると、すべてのファイルをビルド、検証、署名し、評価ゲートを実行して、`release/notes/v2.0.3/` のノートとともにリリースを公開します。
- リレーはコンピューターごとに 1 つのカタログ保持者を置きます。`bridge:catalogUpdate` は保持者が前回アップロードしてからの変更を受け取り（別のプロセスが保持者になると `EXPIRED`）、手放されたカタログはそのコンピューターのすべての crok の受信箱に `catalogWanted` を入れ、`bridge:connect` は `catalog` を一覧に含めます。`sessions:create` は `startedFrom`（`{kind: phone | web | computer, name, at}`）を保存し、ビューアーの `x.ai/remote/sessions` は、ほかの場所から始めたこのコンピューターのセッション（最新の 100 件）を `here` として返します。詳しくは `relay/DESIGN.md` §2–§5 にあります。
- モデルや思考レベルを含む `create` は、`features` に `setup`（crok 2.0.3 が挙げます）または `git`（crok 2.0.1 と 2.0.2）を挙げているホストにだけ渡されます。
- `relay/scripts/sessions-live-e2e.mjs` は、ローカルのリレーに対して 2 台のコンピューターと 1 台のスマートフォンを検証します。実行中のセッションがすぐに一覧に載ること、ディスク上で作成・削除したセッション、保持者の終了、スマートフォンのセッションがコンピューター自身のフロントエンドに届くことを確かめます。`commands-e2e` と `bridge-e2e` は、モデルを選んだセッションがどこで始まり、最初のターンが何で実行されたかも確かめるようになりました。
- スマートフォンアプリのデバッグビルドには、**プロフィール**の右に 3 つ目のタブ **o11y** があります。オーナーの Grafana Cloud のダッシュボード、評価、Agent Observability を、リレーが作るスマートフォン向けのページとして表示します（`o11y:page`、`o11y:refresh`。`mobile/DESIGN.md` の「o11y」、`relay/DESIGN.md` §3）。このリリースのものを含め、リリースビルドにはこのタブはなく、本番リレーでもオフになっています。`relay/scripts/o11y-setup.sh` は読み取り専用のサービスアカウントとデプロイメントの変数を作り、`o11y-preview.mjs` はリレーなしでページを作り、`o11y-demo.mjs` はスマートフォンのデモページを作ります。
- `observability/agento11y/stack.py duplicates [--label]` は、Claude Platform が保存した crok の呼び出しのコピーをレスポンス ID で突き合わせ、それぞれにラベルを付けます。また `gcx_api` は gcx にプレーンな JSON を求めるようになったため、`backfill` が長い会話を飛ばさなくなりました。

### 署名

2.0.3 は、2.0.2、2.0.1、2.0.0、1.5.2、1.5.3 と同じ "Crok Code Signing" 証明書で署名されています。macOS はプライバシー権限を署名に結び付けているため、2.0.2 に許可したもの（「画面収録」、「アクセシビリティ」、マイク、音声認識）は 2.0.3 に引き継がれます。このビルドは公証されていないので、新しくインストールする場合は上記の**このまま開く**の手順が一度必要です。

Android アプリは、2.0.0 で導入されたリリース用の鍵で署名されています。iOS アプリは、**スマートフォンアプリ**で説明しているとおり署名されていません。署名付きのチェックサム一覧は、これとは別のものです。アップデート機能がダウンロードしたファイルを検証するためのもので、macOS によるアプリの扱いは変わりません。

### 2.0.2 からのアップグレード

**Crok Desktop › アップデートを確認…** を使うか、Crok Desktop を終了してからターミナルで `crok upgrade` を実行します。今回のアップデートは、インストール済みの `Crok Desktop.app` にそのまま行われます。そのため Dock や Finder での位置はそのままで、古いコピーがゴミ箱に残ることもありません。アップデートは、インストール済みのアプリと同じ SDK でビルドされたイメージ（macOS26-SDK または macOS15-SDK）を取得し、もう一方になることはありません。

モデルプロバイダへのサインイン、設定、タスク、リレーはいずれも引き継がれます。2.0.3 は 2.0.2 と同じ本番リレーと通信します。リレーで使うコンピューターはすべて更新してください。そうすれば、そのセッションがどこでも最新の状態に保たれます。スマートフォンアプリは、上の**スマートフォンアプリ**で説明しているとおり、更新の必要はありません。

### 詳細

- crok `{{CROK_VERSION}}` を同梱しています。
- GitHub Actions が、`main` のタグ `desktop-v2.0.3`（`{{COMMIT}}`）からビルドしました。macOS 26 SDK のイメージは Xcode {{XCODE26}} と macOS {{SDK26}} SDK、macOS 15 SDK のイメージは Xcode {{XCODE15}} と macOS {{SDK15}} SDK、単体の `crok` は macOS {{TUI_SDK}} SDK でビルドしています。

- iOS アプリ（`dev.chenli.crok.mobile`）は Xcode {{XCODE26}} で作った Release ビルド、Android アプリは Android 8.0 以降向けのリリースビルドです。
- SHA-256 チェックサムは、このノートの末尾と `SHA256SUMS.txt` にあります。`SHA256SUMS.txt` には、スマートフォンアプリも含まれます。一覧の署名を手作業で確認する方法は、リポジトリの `release/README.md` にあります。
