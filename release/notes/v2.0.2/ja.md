Crok Desktop 2.0.2 は、このフォーク向けのネイティブ macOS アプリです。エージェントのランタイムであり `crok` ターミナル UI でもある crok を同梱しているので、ほかに何もインストールする必要はありません。2.0.2 は 2.0.1 に続くリリースで、2.0.1 では両方のスマートフォンアプリをコンピューター、プロジェクト、トピックを軸に作り直しました。2.0.2 では、ブラウザーツールが普段お使いの Chrome で、あなたのサインイン状態のまま動きます。どのデバイスからも、セッションのコンピューターのモデルと思考レベルを選べるようになり、Web アプリはスマートフォンアプリのデザインに合わせ、ターミナルにはリモートパネルが加わりました。ターンの終了は約 1 秒以内に Web とスマートフォンに届きます。Agent Observability はターン全体を追跡し、リリースのワークフローは公開の前に評価スイートを実行できます。

このリリースも 2.0.1 と同様に、プルリクエストがマージされるとすぐに GitHub Actions がビルドして公開します。

### インストール

1. お使いの macOS のバージョンに合ったディスクイメージをダウンロードして開きます。どちらを選ぶかは**どのディスクイメージをダウンロードするか**の表をご覧ください。
2. **Crok Desktop** を**アプリケーション**にドラッグします。
3. アプリケーションから Crok Desktop を開きます。このビルドは公証されていないため、初回は macOS がアプリを検証できないと表示します。メッセージを閉じ、**システム設定 › プライバシーとセキュリティ**を開いて、Crok Desktop のメッセージの横にある**このまま開く**をクリックし、確認してください。この操作は一度だけです。
4. **設定 › アカウント**で、OpenRouter、OpenAI Codex、Anthropic API キー、DeepSeek API キー、または GLM Coding Plan のキーでサインインします。

Apple シリコン（M1 以降）を搭載した Mac と、macOS 14 Sonoma 以降が必要です。

### どのディスクイメージをダウンロードするか

どちらのイメージも Crok Desktop 2.0.2 で、機能は同じです。違いはビルドに使った macOS SDK だけで、これによってウインドウの外観に Apple の Liquid Glass が使われるかどうかが決まります。

| ディスクイメージ | ビルドに使った SDK | 対象 | タイトルバー |
| --- | --- | --- | --- |
| `Crok-Desktop-2.0.2-arm64-macOS26-SDK.dmg` | macOS {{SDK26}} SDK | macOS 26 以降 | Liquid Glass |
| `Crok-Desktop-2.0.2-arm64-macOS15-SDK.dmg` | macOS {{SDK15}} SDK | macOS 14 と 15 | ウインドウ内のすりガラス風のぼかし |

macOS 26 以降では、タイトルバーが Liquid Glass になる macOS 26 SDK のイメージをおすすめします。macOS 14 または 15 では、macOS 15 SDK のイメージを使ってください。こちらはそれ以降のバージョンでも動くので、macOS のバージョンがわからない場合はこちらが安全です。

`crok-2.0.2-aarch64-apple-darwin.tar.gz` は `crok` ターミナル UI 単体で、アプリを入れたくない Mac 向けです。展開して `crok` を `PATH` の通った場所に置いてください。スマートフォンアプリについては、**スマートフォンアプリ**で説明しています。`SHA256SUMS.txt` はすべてのダウンロードファイルの SHA-256 の一覧、`SHA256SUMS.txt.sig` はその一覧の署名で、アップデート機能がこれを検証します。

### スマートフォンアプリ

iPhone と Android 向けの Crok アプリは、お使いのコンピューターのセッションを追いかけ、その応答と権限の要求を表示し、どこからでもタスクを開始したり操作したりできます。2.0.1 と同様に、このリリースに含まれます。3 つのファイルはいずれも本番リレーにサインインします。

- **Android 8.0 以降**：スマートフォンで `Crok-Android-2.0.2.apk` をダウンロードして開きます。Android に求められたら、ブラウザにアプリのインストールを許可してください。または `adb install -r Crok-Android-2.0.2.apk` を実行します。この APK は今後のリリースでも使い続けるリリース用の鍵で署名されているため、次の APK はこの上にそのままインストールできます。自分でビルドした Crok の APK は別の鍵で署名されていて、インストールを妨げます。先に `adb uninstall dev.chenli.crok.mobile` を実行するか、スマートフォンの設定から削除してください。
- **iPhone と iPad、iOS 17 以降**：`Crok-iOS-2.0.2-unsigned.ipa` は署名されていません。iOS デバイス向けのアプリは、インストールする人の Apple ID で署名されるためです。AltStore や Sideloadly などのサイドロードツールでインストールしてください。これらのツールがお使いの Apple ID で署名します。無料の Apple ID の場合、7 日たつと、もう一度インストールするまで iOS はアプリを開かなくなります。代わりに自分でビルドする場合は、**Release** 構成を使ってください。Xcode の Run ボタンは Debug をビルドし、そちらはテスト用リレーにサインインします。
- **iOS シミュレータ**：`Crok-iOS-2.0.2-Simulator.zip` を展開すると `Crok.app` になります。Xcode のある Mac で `xcrun simctl install booted Crok.app` を実行するためのものです。

スマートフォンをサインインさせるには、**GitHub または Google で続ける**をタップし、開いた https://crok.chenli.dev のページでサインインして、**承認**をタップします。続いて、各コンピューターをリンクします。そのコンピューターで `crok remote login` を実行し、表示された QR コードをアプリの**設定 › コンピュータをリンク**から読み取るか、開いた Web ページでそのコンピューターを承認してください。

### ハイライト

- **ブラウザーツールがお使いの Chrome で動きます。** 起動中のブラウザーに、最後に使ったプロファイルでウィンドウを開くので、サインイン済みのサイトはサインインしたままです。Chrome での一度きりの設定と、あなたの **Allow** が必要です。下の**自分のブラウザー**を参照してください。
- **どのデバイスでもセッションのモデルと思考レベルを選べます。** iPhone、Android、Web では、新しいセッションでも開いているセッションでも、入力欄の上に 2 つのピルが表示されます。モデル（検索でき、プロバイダーごとにまとめられたシートが開きます）と思考レベルです。Crok Desktop の**ほかのコンピューター**で新しいタスクを作るときも、始める前に同じ選択ができます。
- **何百ものモデルを持つコンピューターも、そのすべてを提供します。** OpenRouter にサインインしたコンピューターは約 480 のモデルを一覧にします。中継はこれまで 200 を超える一覧を拒否していたため、そうしたコンピューターは何も選ばせられませんでした。今は最大 1,000 まで保持します。
- **Web アプリがスマートフォンアプリのデザインに合わせました。** レイアウトは Telegram Web に似ていて、左に選択中のコンピューターのプロジェクトとそのトピック、中央にテーマ付きのセッション、右にセッション情報があります。
- **ターミナルのリモートパネル。** `/remote` は Crok Desktop の**ほかのコンピューター**と同じように、ほかのコンピューター、そのプロジェクトとセッションを表示し、`n` で選んだモデルのセッションをそこで始めます。
- **ターンの終了がすぐに Web とスマートフォンに届きます。** 忙しいターンのあとは、コンピューターが終わってからも数秒、ときには数分、セッションが作業中と表示されていました。今は約 1 秒以内に終了が届きます。
- **長いセッションもスマートフォンですばやく開きます。** スマートフォンアプリはトランスクリプトを小さなライブの部分に分けて読み込み、新しいセッションの最初のプロンプトを見える位置に保ち、思考とツール呼び出しを Crok Desktop と同じように状態だけで表示します。
- **OpenRouter の 100 万トークンのモデルが 10.5 万トークンを超えても使えます。** crok はプロンプトの入る余地のない出力枠を要求していたため、会話が長くなると OpenRouter に拒否されていました。今はプロンプトの横に収まる分だけの出力を要求します。
- **Agent Observability がターン全体を追跡します。** 各ターンはモデル呼び出しとツール実行を含む 1 つのトレースになり、メンテナーのスタックが実際のトラフィックを採点し、何かを変更しうるツール呼び出しをチェックします。下の **Agent Observability** を参照してください。

### 自分のブラウザー

ブラウザーツールはこれまで、Crok 専用のプロファイルで自前のブラウザーを起動していました。今は起動中の Chrome に、最後に使ったプロファイルでウィンドウを開くので、サインイン済みのサイトはどれもサインインしたままです。モデルには、そのウィンドウがあなたとしてサインインしている場合があると伝えられます。

- **リモートデバッグを一度だけ有効にします。** Chrome 144 以降が必要です。Chrome で `chrome://inspect/#remote-debugging` を開き、**Allow remote debugging for this browser instance** をオンにします。Chrome はほかのアプリから渡された `chrome://` アドレスを開かないため、Crok Desktop の**設定 › ブラウザとコンピュータの操作**に**アドレスをコピー**ボタンがあります。
- **タスクごとに一度許可します。** タスクが初めてブラウザーを使うとき、Chrome が **Allow remote debugging?** と尋ねるので、**Allow** をクリックします。Crok は 2 分間返事を待ち、リモートデバッグがオフのときや拒否されたときは、どうすればよいかを伝えます。
- **ブラウザーはあなたのものです。** Crok はブラウザーを終了させず、起動時のタブも乗っ取りません。ダウンロードは Chrome の設定どおりの場所に保存されます。
- **Crok 専用のプロファイルも使えます。** Crok Desktop の**設定 › ブラウザとコンピュータの操作 › ブラウザのプロファイル**で **Crok 専用のプロファイル**を選ぶか、`~/.crok/config.toml` の `[toolset.browser]` に `profile = "crok"` と書きます。既定は `profile = "user"` です。

macOS の Chrome でテストしました。Edge、Brave、Chromium はまだテストしていません。

### リモートコントロール

このリリースのすべての crok は、2.0.1 と同じく https://crok.chenli.dev の本番中継にサインインし、すでにあるサインインをそのまま使います。

- **モデルと思考レベル。** 新しいセッションでは、選ぶまでピルに **Default** と表示され、セッションは選んだ内容で始まります。開いているセッションで変更すると、そのコンピューターに送られ、コンピューターが適用するまでピルが回ります。拒否された場合は元の値に戻り、理由が表示されます。セッション情報にも同じ 2 行があり、スマートフォンの `/model` と `/think` コマンドも同じ一覧を読みます。
- **Web アプリ。** 左の列はページの積み重ねです。選択中のコンピューターのセッションとそのプロジェクト、プロジェクトのトピック、アーカイブしたセッション、プロフィールがあります。トピックにはホバー時の操作と右クリックメニューがあり、ピン留め、停止、既読にする、アーカイブ、並べ替えができます。セッションのテーマとカラーモードはブラウザーに保存されます。幅が 1024 ピクセル未満のときは、一度に 1 列だけを表示します。
- **ターミナルのリモートパネル。** `/remote` と `/remote open` は、アカウント、このコンピューター、接続を表示し、続いてほかのコンピューター（オンラインか最終接続時刻、未読数）、そのプロジェクト、各プロジェクトのセッションのツリーを表示します。Enter で `/resume` と同じようにセッションを開き、`n` でそのコンピューターのモデルと思考レベルを尋ねてからセッションを始め、文字を入力するとツリーを絞り込みます。`/remote status` は以前のテキストを表示します。ほかのコンピューターのセッションはステータス行にブランチと token の数値を表示し、そこでの `/model` はこのコンピューターの既定を変更しなくなりました。
- **ターンの終了がすぐに届きます。** 中継との接続は、各書き込みの前に待っている更新を 1 つにまとめるようになったため、忙しいターンが終了を遅らせるキューを作らなくなりました。キューに入ったプロンプトが実行されずにキューから外れても、終わったターンは終了と表示され、そのあとスマートフォンから送ったプロンプトも実行されます。
- **スマートフォンは長いセッションを分けて読み込みます。** スマートフォンアプリはトランスクリプトを最新の 40 件で開き、スクロールに合わせて古いものを 60 件ずつ読み込むので、何週間もミラーされたセッションも遅いネットワークですばやく開きます。新しいセッションの最初のプロンプトは入力欄の上に残ります。思考は実行中から完了へ、ツール呼び出しは実行中、完了、失敗、停止として表示されます。中継は思考のテキストやツールの出力をスマートフォンに送らなくなりました。
- **コンピューターとスマートフォンを更新してください。** モデルの一覧と速くなったターンの終了は、セッションのあるコンピューターの crok 2.0.2 で、ピルとトランスクリプトのウィンドウは 2.0.2 のスマートフォンアプリで使えます。2.0.1 のスマートフォンアプリも引き続き中継で動作します。

### Agent Observability

2.0.1 と同様に、このリリースのすべての crok は、自分が行うモデル呼び出しを 1 回ごとに、メンテナーの Grafana Cloud スタック上の [Grafana Agent Observability](https://grafana.com/docs/grafana-cloud/machine-learning/agent-observability/) に報告します。報告先のホストは `crok version --json` の `agentObservability` に表示されます。2.0.2 では、呼び出しの間に起きることも報告します。

- **ターンとツール実行。** ターンは 1 つのトレースで、そのルートスパンがターンのモデル呼び出しとツール実行を含み、ターンがどう終わったか、呼び出しとツールエラーがいくつあったかを記録します。ツール実行は結果、種類、終了コード、出力のサイズを記録し、引数や出力の中身は記録しません。サブエージェントのターンは、それを始めたターンの下に入ります。
- **ステップ、判定、評価。** 権限の判断、PreToolUse フックの結果、圧縮、MCP サーバーの起動は、会話上のステップとして表示されます。crok 自身のゴール評価、怠慢分類、同一呼び出しガード、ターン上限はスコアを報告し、あなたが付けた評価も xAI に加えてここに送られます。
- **タグ。** 呼び出しには `origin`（`local`、`crok -p` なら `headless`、Web とスマートフォンからのプロンプトなら `relay`、実験なら `eval`）と、`repo`、`branch`、そしてコンピューターのログイン名である `user` が付きます。
- **ガードのチェック（警告モード）。** 何かを変更しうるツール呼び出しを実行する前と、ツールの結果をモデルに返す前に、crok はそれをスタックのガードに送り、履歴を書き換える git コマンド、破壊的なシェルコマンド、本番用の鍵がないかを確かめます。crok は返事を待たず、呼び出しを止めることもありません。一致したものは会話上の警告として記録されます。`CROK_AGENTO11Y_GUARDS=off` でチェックを止められます。
- **メトリクス。** `crok_turns_total`、`crok_tool_runs_total`、`crok_workflow_steps_total`、`crok_guard_checks_total` と、ターンとツールの所要時間が、スタックのハーネスダッシュボード、アラート、SLO に使われます。

報告をやめるには、`~/.crok/config.toml` の `[features]` に `agent_observability = false` を追加するか、`CROK_AGENT_OBSERVABILITY=0` を設定します。自分のスタックに報告するには、リポジトリの `crates/codegen/xai-grok-agento11y/setup.sh` で `~/.crok/agento11y.env` を書きます。

### 開発者向け

- リリースはこれまでどおり `.github/workflows/release.yml` が行います。`VERSION` を上げたプルリクエストが `main` にマージされると、すべてのファイルをビルド、検証、署名し、`release/notes/v2.0.2/` のノートとともにリリースを公開します。
- リリースのワークフローに新しい `eval` ジョブが加わり、`publish` はその完了を待ちます。リリースビルドに対して `evals/run.py` の 7 つのスモークケースをそれぞれ 2 回実行し、pass@1 が `evals/baselines/smoke.json` より 0.20 を超えて下がったとき、またはこれまで常に合格していた安全性のケースが失敗したときに失敗します。release 環境に `CROK_EVAL_OPENROUTER_API_KEY` シークレットがないときは、警告を出して合格にします。
- `evals/run.py` は小さなフィクスチャーリポジトリ上で crok をヘッドレスで実行します。スイートは 3 つ（`s1` 回帰、`s2` ツールの使用、`s3` 安全性、計 22 ケース）で、モデルとビルドごとに合格率、コスト、振る舞いを報告します。ケースとチェックは `evals/README.md` で説明しています。
- `observability/agento11y/stack.json` にスタックの評価器、ルール、ガードがあり、`observability/agento11y/stack.py` がそれらを Agent Observability プラグイン API で適用し、ルールができる前に保存された会話を採点し、アラートと SLO をインストールします。
- サンプラーは `crates/codegen/xai-grok-sampler/src/observe_harness.rs` を通じて各ターン、ツール実行、ステップ、判定、評価、ガードのチェックを報告し、ブリッジが `crates/codegen/xai-grok-agento11y/bridge/src/harness.ts` で記録します。
- 中継の `sessions:transcript` は、スマートフォンのトランスクリプトのウィンドウ向けに、セッションの項目の範囲を新しい順に、思考とツール出力のテキストを除いて返します（`relay/DESIGN.md` §3）。`bridge:setModels` は最大 1,000 のモデルを保持し、`devices:models` がクライアントの読む一覧で、crok のビューアーは `x.ai/remote/models` でそれを求めます。
- 中継との接続は、セッションで待っている更新を 1 回の書き込みにまとめ（`fold_backlog`）、`relay/scripts/status-e2e.mjs` は遅い中継越しにスマートフォンがどれだけ早くターンの終了を知るかを測ります。
- OpenRouter へのリクエストは、`max_tokens` をコンテキストウィンドウから推定したプロンプトを引いた値に合わせます。

### 署名

2.0.2 は、2.0.1、2.0.0、1.5.2、1.5.3 と同じ "Crok Code Signing" 証明書で署名されています。macOS はプライバシー権限を署名に結び付けているため、2.0.1 に許可したもの（「画面収録」、「アクセシビリティ」、マイク、音声認識）は 2.0.2 に引き継がれます。このビルドは公証されていないので、新しくインストールする場合は上記の**このまま開く**の手順が一度必要です。

Android アプリは、2.0.0 で導入されたリリース用の鍵で署名されています。iOS アプリは、**スマートフォンアプリ**で説明しているとおり署名されていません。署名付きのチェックサム一覧は、これとは別のものです。アップデート機能がダウンロードしたファイルを検証するためのもので、macOS によるアプリの扱いは変わりません。

### 2.0.1 からのアップグレード

**Crok Desktop › アップデートを確認…** を使うか、Crok Desktop を終了してからターミナルで `crok upgrade` を実行します。今回のアップデートは、インストール済みの `Crok Desktop.app` にそのまま行われます。そのため Dock や Finder での位置はそのままで、古いコピーがゴミ箱に残ることもありません。アップデートは、インストール済みのアプリと同じ SDK でビルドされたイメージ（macOS26-SDK または macOS15-SDK）を取得し、もう一方になることはありません。

モデルプロバイダへのサインイン、設定、タスク、リレーはいずれも引き継がれます。2.0.2 は 2.0.1 と同じ本番リレーと通信します。スマートフォンアプリは、上の**スマートフォンアプリ**の説明どおり、このリリースのファイルからインストールします。

### 詳細

- crok `{{CROK_VERSION}}` を同梱しています。
